What Next does

Next pans the viewport through frames on the current page using a compact prev / next bar.

Controls

  • Right-click (Mac: Control-click or two-finger tap), Escape, or long-press prev/next — open this settings panel
  • Plugin ← → buttons — step the slide list (see Slide order). With Always follow connectors on, they prefer connectors instead. With vertical buttons on, ↑ / ↓ move by column order and the center control zooms to the current canvas selection if it’s in the sequence.
  • N, Space, Tab, Enter, ] — same as the plugin → button
  • B, Backspace, [ — same as the plugin ← button
  • Arrow keys / WASD / JK — move by direction; in FigJam these prefer connectors when present
  • + / − — zoom in / out
  • 0–9 — set transition speed (0 = instant, 1 = slowest, 9 = fastest)
  • Shift — 2000ms glide for the next move
  • Escape — open or close settings

Slide order

By default, Next builds a list of objects sorted in row order: left → right along a row, then down to the next row. For example:

A  B
C  D
E

becomes A → B → C → D → E.

The plugin ← → buttons (and N / B / Space / etc.) walk that list one step at a time.

Nested slides: when a section (or other container) is itself a slide and also contains slides inside it, the list visits the container first, then its inner objects, before moving on to the next container. So you “step into” frames within frames as part of normal order.

Up/Down (and W/S) use a separate top → bottom ordering.

If a top-level vector named journey or camera exists, that path replaces this spatial list entirely.

Connectors

In FigJam, objects can be linked with connector lines. Arrow keys (and WASD / JK) try to follow a connector from the current object in that direction — for example Right follows a link toward something on the right. If nothing matches, they fall back to slide order.

The plugin ← → buttons do not follow connectors unless you turn on Always follow connectors in Options. That setting makes those buttons (and N / B / Space / etc.) prefer left/right connectors the same way the arrow keys do.

When following connectors, also prioritise frames within frames (on by default) keeps nested slide order: Next still steps into inner objects before jumping along a connector away from a container. Turn it off if connectors should win immediately.

When following connectors, literally follow the connectors moves the camera along the connector’s drawn path (elbows, curves, rounded corners) instead of a straight glide. This is reconstructed from the connector SVG outline and only works reliably on solid lines without arrowheads (Next then falls back to a normal glide).

The other end of the connector must also be a type you’ve enabled under Treat as frames.

Camera / journey path

In Figma Design (and optionally FigJam), place a top-level vector named journey or camera to drive navigation along its points instead of spatial frame order. Frames don’t need side anchors — you draw the path yourself; Next reads the vector’s real centerline (vectorNetwork) and steps between vertices.

  • Vertex stroke join Miter — stop
  • Round — passthrough (auto-continue); disabled in FigJam
  • Bevel — instant
